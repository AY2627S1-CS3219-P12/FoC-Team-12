# Report freeze and dispute finalization

> The synchronous dispute write protocol below is superseded by [Kafka dispute coordination](dispute-kafka-contract.md). Applied migrations, domain freeze rules, original evidence and unrelated APIs remain.

Approved in the report-view UX continuation on 10 November 2026. This task is the shared editor; Darryl (Admin/User), XueTing (Order) and Eldridge (Chat/Credit) review their boundaries before merge and rollout. This extends the Chat/Admin contract without transferring database ownership.

## Ownership and state

Admin owns statements, membership, reviewer independence, the immutable decision and closure operation. Its existing OPEN, UNDER_REVIEW and RESOLVED case states remain unchanged. Order owns a separate review barrier associated with the case UUID; an unresolved barrier preserves the original lifecycle state and blocks edit, accept, withdraw, pickup, delivery, completion, cancellation and expiry. Discovery excludes reviewed errands. Chat owns the durable errand-chat barrier. Credit exclusively applies the reservation disposition.

A successful report acknowledges both barriers. Admin first persists a report preparation bound to actor, order, text hash and operation UUID. Admin calls Order POST /internal/orders/{orderId}/review using an audience-pinned service assertion plus the original current user token. Order checks the participant against its own requester/current and historical courier records, freezes under its row lock and returns authoritative participants. Chat POST /internal/chat/orders/{orderId}/review independently confirms the Order snapshot and actor, stores its own barrier and drains existing errand conversation writers. Admin then commits the statement, participants, audit, outbox and original response together. A new case uses a deterministic case UUID per order so concurrent first reports converge. Failure never produces a successful report receipt; a committed freeze remains in place while the original request is resumed. There is no automatic unfreeze or unsafe compensation.

Verified participants may read their case, add their one statement while unresolved and use their own private admin conversation. They cannot read another participant's private conversation. An independent assigned reviewer may open conversations and perform approved actions for verified nonreporters too. Membership comes from authoritative Order history and complete evidence, never an arbitrary browser UUID. Reviewer independence remains enforced.

## Resolution and credits

Admin prepares one actor/body/revision-bound closure operation, blocks new case mutations, drains private case writers through the existing Chat closure barrier, then asks Order to finalize with that operation UUID and explicit disposition. No service holds its local database lock during another service call.

Order persists the original case/operation/disposition before calling Credit POST /internal/credits/orders/{orderId}/dispute-resolution. Credit accepts only the pinned Order caller plus a currently eligible ADMIN actor. It locks the reservation, applies existing release/settlement domain logic, and atomically stores ledger effects, an original receipt and DisputeCreditsFinalized outbox evidence. RETURN_TO_REQUESTER releases an active hold; PAY_COURIER pays the full active hold to Order's assigned courier; KEEP_EXISTING is allowed only for an absent or already finalized reservation. Credit corrections remain a separate available-balance operation and cannot substitute for releasing a hold.

Credit binds operation, case, order, actor, requester, courier and disposition. Identical retries return the original response; changed identities/body or a second operation for the same case/order conflict. Order retries Credit with the original operation after uncertain responses. Only confirmed Credit completion permits Order finalization. Nonterminal errands become the existing COMPLETED state with DISPUTE_RESOLVED reason; terminal errands retain their prior lifecycle result. Both carry review resolution metadata. Order publishes the factual lifecycle transition with CreditEffect.NONE, never an ordinary OrderCompleted payout command. Admin refreshes complete authoritative evidence after finalization before committing RESOLVED and CaseResolved. If any acknowledgement/evidence is unavailable, closure remains pending and the UI resumes the original request. No timeout is treated as success.

## Timeline and images

Chat merges original TEXT, QUICK_REPLY and IMAGE messages with existing producer evidence in chronological order, including errand assignment epochs and only the current case's private threads. SYSTEM lifecycle messages are omitted to avoid duplicate timeline facts. A pinned timeline snapshot retains its message set across pagination; later messages appear on refresh. The case-scoped chat.messages checkpoint describes that local snapshot. Original text is shown verbatim, without LLM rewriting.

Images expose metadata only in evidence. Admin's authenticated case/message attachment route proxies Chat's protected storage read, rechecking current access; URLs and storage keys are not returned in evidence. Responses are no-store and restricted to supported image types and size. Ordinary participant conversation privacy remains unchanged.

## Presentation and rollout

Errands show a separate Under review section and text badge with paused-at lifecycle status. A notice explains that a party reported an issue, actions are paused, and the other party may add a statement. Resolved errands move to Past and show Resolved after review. Private admin chat is available until closure; normal errand chat stays read-only.

Before enabling, apply each owner's migrations and configure Admin -> Order and Order -> Credit URLs and public-key pins, preserving Chat's existing pins. Compose defaults and staging manifests include the new URLs; staging secret preparation merges the new caller pins. No keys are generated or deployment performed by this iteration. The composed local default-deny policies include both ends of Admin -> Order and Order -> Credit, and the network regression script checks the new edges while denying direct Admin -> Credit access. This iteration does not claim cluster acceptance; policies and trust pins must be applied together by the runtime integration owner.

Preexisting cases do not retroactively have Order review metadata. The first claim or resolution establishes barriers; operators must reconcile all existing unresolved cases before enabling normal traffic if an immediate global freeze is required. A report preparation without a case remains an observable durable retry intent, never a closed/accepted case. Monitor report preparations without completed mutation receipts, pending closure preparations, Credit receipts/outbox and Order review metadata by order/case/operation UUID; resume the original actor/body/key after outages. No background reconciliation invents a resolution or selects a credit outcome.
